# Telegram-бот-магазин

Полноценный Telegram-бот для продажи легальных невозрастных товаров. Каталог,
корзина, оформление заказа, оплата по реквизитам с загрузкой чека,
подтверждение администратором, отзывы, техподдержка, рассылка, статистика,
логи и полноценная админ-панель — всё редактируется через Telegram, без
изменения кода.

## Технологии

- Python 3.12+, aiogram 3.x
- PostgreSQL + SQLAlchemy 2.x (async)
- Redis (хранение FSM-состояний)
- Docker / docker-compose
- Alembic (миграции, опционально — по умолчанию таблицы создаются автоматически)

## Деплой на Railway через GitHub (без компьютера, всё из браузера)

### 1. Залейте проект на GitHub

1. Откройте [github.com](https://github.com) в браузере телефона → **+** → **New repository**.
   Назовите его, например, `telegram-shop`, оставьте **Private** или **Public** — на ваш выбор.
2. На странице нового (пустого) репозитория нажмите **uploading an existing file**
   (или Add file → Upload files).
3. Перетащите/выберите **все файлы и папки** из этого архива (можно по одной
   папке за раз — GitHub позволяет загружать вложенные структуры).
4. Внизу нажмите **Commit changes**.

> Проверьте, что в репозитории попал файл `.env.example`, а не `.env` — секретный
> токен никогда не должен лежать в git.

### 2. Создайте проект на Railway

1. На [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**
   → выберите только что созданный репозиторий.
2. Railway увидит `Dockerfile` и `railway.toml` и соберёт бота автоматически —
   но пока не запустится, потому что не хватает переменных окружения и БД.

### 3. Добавьте PostgreSQL и Redis

В том же проекте Railway:

1. **New** → **Database** → **Add PostgreSQL**.
2. **New** → **Database** → **Add Redis**.

Railway сам создаёт для них `DATABASE_URL` и `REDIS_URL`.

### 4. Подключите переменные к сервису бота

Откройте сервис бота (не Postgres/Redis) → вкладка **Variables** → добавьте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `SUPER_ADMIN_IDS` | ваш Telegram ID (узнать у @userinfobot) |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` — Railway подставит ссылкой на сервис Postgres |
| `REDIS_URL` | `${{Redis.REDIS_URL}}` — ссылкой на сервис Redis |

(Начните вводить `${{` — Railway покажет автоподсказку с доступными сервисами
и их переменными.)

### 5. Деплой

Railway пересоберёт и перезапустит сервис автоматически после сохранения
переменных. Откройте вкладку **Deployments** → **View Logs** — если видите
`Bot started`, всё работает. Напишите боту `/start` в Telegram.

Дальше **менять код не нужно**: все тексты, категории, товары, реквизиты
оплаты и администраторы редактируются прямо в Telegram через `/admin`. Чтобы
обновить сам код в будущем — загрузите изменённые файлы в GitHub так же через
веб-интерфейс, Railway передеплоит их сама.

## Альтернатива: Docker Compose на своём компьютере/сервере

Если запускаете не на Railway, а локально или на VPS:

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `SUPER_ADMIN_IDS`.
2. Запустите:

   ```bash
   docker compose up --build -d
   ```

Бот сам создаст таблицы в PostgreSQL при первом запуске и назначит указанные
в `SUPER_ADMIN_IDS` администраторами с ролью `SUPER_ADMIN`.

3. (Необязательно) наполнить магазин демо-данными:

   ```bash
   docker compose exec bot python scripts/seed.py
   ```

## Запуск без Docker

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# нужны локальные PostgreSQL и Redis, см. DATABASE_URL / REDIS_URL в .env
cp .env.example .env  # заполните BOT_TOKEN и SUPER_ADMIN_IDS

python bot.py
```

## Структура проекта

```
bot.py               — точка запуска
config.py            — конфигурация из .env
database.py          — подключение к PostgreSQL (SQLAlchemy async)
models.py            — модели БД
keyboards.py         — inline-клавиатуры
states.py            — FSM-состояния
filters.py           — проверка админ-доступа и бана
middleware.py         — глобальная проверка бана пользователя
utils.py             — общие вспомогательные функции

handlers/            — пользовательская часть бота
admin/               — админ-панель (/admin)
services/            — бизнес-логика (работа с БД)
alembic/              — миграции базы данных (опционально)
scripts/seed.py       — наполнение демо-данными
railway.toml          — конфигурация деплоя на Railway
uploads/              — служебная папка (сами файлы хранятся в Telegram по file_id)
```

## Сценарий пользователя

`/start` → 🛍 Каталог → выбор категории → товар (фото, описание, характеристики)
→ 🛒 Купить → (вариант, если есть) → количество → адрес доставки → сводка заказа
→ 💳 Перейти к оплате → выбор способа оплаты → реквизиты → отправка чека →
⏳ Ожидает подтверждения → администратор подтверждает/отклоняет → уведомление
пользователю → 📦 Мои заказы (история и статусы).

## Админ-панель

`/admin` (доступ только для Telegram ID из таблицы `admins`):

📊 Статистика · 📦 Заказы · 🛍 Товары · 📁 Категории · 💳 Оплата · ⭐ Отзывы ·
🆘 Техподдержка · 📢 Рассылка · 👥 Пользователи · 🚫 Бан/Разбан ·
👑 Администраторы (SUPER_ADMIN / ADMIN / SUPPORT) · 📜 Логи · 💰 Доход ·
⚙️ Настройки.

Все тексты, кнопки, реквизиты оплаты, категории и товары редактируются прямо
в Telegram — в коде ничего не хардкодится.

### Роли администраторов

- **SUPER_ADMIN** — полный доступ, включая управление другими администраторами.
- **ADMIN** — управление магазином и заказами.
- **SUPPORT** — работа с поддержкой и заказами, без доступа к критическим
  настройкам (управление админами доступно только SUPER_ADMIN — проверяется
  в `admin/admins.py`).

## Безопасность

- Доступ к `/admin` и ко всем административным разделам проверяется по
  Telegram ID через таблицу `admins` (фильтр `IsAdmin` в `filters.py`).
- Заблокированные пользователи (`users.is_banned`) не могут пользоваться ботом
  — проверка идёт в глобальном middleware.
- Реквизиты оплаты и все тексты хранятся в базе данных, а не в коде.
- Секреты (токен бота, пароли БД) читаются только из `.env`.
- Изменения статусов заказов и подтверждение оплаты идут через транзакционные
  операции SQLAlchemy.

## Примечания по реализации

- В MVP-модели один заказ соответствует одной позиции корзины (товар +
  вариант + количество) — это самый частый сценарий для магазина в Telegram
  и заметно упрощает FSM оформления заказа. Модель `OrderItem` уже
  спроектирована так, что переход к «настоящей» многотоварной корзине не
  требует миграции схемы — только доработки хендлеров `handlers/cart.py`.
- Таблицы создаются автоматически при старте бота (`database.init_models`).
  Для production-развёртывания с контролируемыми миграциями используйте
  Alembic (`alembic revision --autogenerate -m "init"` → `alembic upgrade head`).
